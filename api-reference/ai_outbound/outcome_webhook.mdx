## Overview

When you trigger an [AI outbound contact](/api-reference/ai_outbound/create) with a `callback_url`, Oliver sends an HTTP POST request to that URL once the request reaches a terminal status (`completed`, `suppressed`, or `failed`). Exactly one outcome webhook is delivered per request, and only when a `callback_url` was provided.

The outcome is also always available by polling [`GET /ai_outbound/requests/{id}`](/api-reference/ai_outbound/show) — the webhook simply lets you close the loop without polling.

<Note>
  Suppressed requests still fire an outcome webhook. A suppression is a legitimate terminal outcome (for example, the client was contacted too recently), not an error.
</Note>

## Payload Structure

The webhook payload is sent as a JSON object with the following structure:

<ResponseField name="event" type="string" required>
  The event name, in the form `ai_outbound.{status}` — e.g. `ai_outbound.completed`, `ai_outbound.suppressed`, or `ai_outbound.failed`.
</ResponseField>

<ResponseField name="request_id" type="string" required>
  Oliver's unique identifier for the request.
</ResponseField>

<ResponseField name="partner_request_id" type="string">
  The idempotency key you supplied when creating the request, if any.
</ResponseField>

<ResponseField name="clinic_id" type="string" required>
  Oliver's identifier for the practice (the value you send in the `X-Client-Id` header).
</ResponseField>

<ResponseField name="channel" type="string" required>
  The outreach channel. One of `sms`, `voice`.
</ResponseField>

<ResponseField name="purpose" type="string" required>
  The purpose of the outreach. One of `scheduling`, `callback_followup`, `refill`, `general`.
</ResponseField>

<ResponseField name="status" type="string" required>
  The terminal status of the request. One of `completed`, `suppressed`, `failed`.
</ResponseField>

<ResponseField name="outcome" type="string">
  For a `completed` request, the resolution. One of `booked`, `opted_out`, `no_response`, `undeliverable`.
</ResponseField>

<ResponseField name="outcome_detail" type="string">
  Optional additional detail about the outcome, when available.
</ResponseField>

<ResponseField name="suppression_reason" type="string">
  Why the request was suppressed, when `status` is `suppressed`. E.g. `recent_contact`, `active_conversation`, `sms_opted_out`, `voice_not_supported`.
</ResponseField>

<ResponseField name="error_message" type="string">
  Failure detail, when `status` is `failed`.
</ResponseField>

<ResponseField name="client_id" type="string">
  Oliver's identifier for the resolved client.
</ResponseField>

<ResponseField name="patient_id" type="string">
  Oliver's identifier for the resolved patient, if applicable.
</ResponseField>

<ResponseField name="contacted_at" type="string">
  When the first outbound message was sent, in ISO 8601 format. Null if the client was never contacted (e.g. suppressed).
</ResponseField>

<ResponseField name="completed_at" type="string" required>
  When the request reached its terminal status, in ISO 8601 format.
</ResponseField>

<ResponseField name="timestamp" type="string" required>
  When the webhook was sent, in ISO 8601 format.
</ResponseField>

## Verifying Webhook Signatures

When your practice has an AI outbound webhook secret configured, each request includes a signature in the `X-Webhook-Signature` header. You should verify this signature before processing the payload.

### Signature Verification Process

1. Extract the `X-Webhook-Signature` header from the request
2. Compute an HMAC-SHA256 hash of the raw request body using your webhook secret
3. Compare the computed signature with the one in the header

### Example Verification

```python
import hmac
import hashlib

def verify_webhook_signature(payload: bytes, signature: str, secret: str) -> bool:
    expected_signature = hmac.new(
        secret.encode('utf-8'),
        payload,
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected_signature, signature)
```

```javascript
const crypto = require('crypto');

function verifyWebhookSignature(payload, signature, secret) {
  const expectedSignature = crypto
    .createHmac('sha256', secret)
    .update(payload, 'utf-8')
    .digest('hex');
  return crypto.timingSafeEqual(
    Buffer.from(expectedSignature),
    Buffer.from(signature)
  );
}
```

<Warning>
  Always use constant-time comparison functions (like `hmac.compare_digest` in Python or `crypto.timingSafeEqual` in Node.js) to prevent timing attacks.
</Warning>

## Delivery and Retries

- Webhooks are delivered by an HTTP POST with a `Content-Type: application/json` body.
- Respond with a `200 OK` status code to acknowledge receipt. Process asynchronously if needed to avoid timeouts.
- If your endpoint does not respond successfully, Oliver retries delivery up to 3 times with exponential backoff before marking the webhook as failed.
