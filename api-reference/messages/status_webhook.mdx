## Overview

When you [send a message](/api-reference/messages/create) with a `callback_url`, Oliver POSTs to that URL each time the message's status changes. The current status is also always available from [`GET /messages/{id}`](/api-reference/messages/show).

## When the webhook fires

| Event | Fires when |
| --- | --- |
| `message.sent` | The message was handed to the carrier. |
| `message.delivered` | It reached the client's phone. |
| `message.read` | The client opened it (RCS only). |
| `message.failed` | It couldn't be delivered. `error_code` and `error_message` say why. |
| `message.suppressed` | It was not sent because the client opted out (`status_reason: "opted_out"`) or the number can't receive texts (`blocked_number`). |
| `message.expired` | It was held for the practice's sending hours and `expires_at` passed first. |

A message held for sending hours (`scheduled`) doesn't fire a webhook; your create call already returned that status.

Each status is sent once, in order. If statuses change faster than they can be delivered, you get the latest one, e.g. `message.read` without a separate `message.delivered`. Branch on `status`, and treat a status at or past one you already handled as a no-op.

## Payload

The body is the [message object](/api-reference/messages/show) plus these fields:

<ResponseField name="event" type="string" required>
  `message.{status}`, e.g. `message.delivered`.
</ResponseField>

<ResponseField name="event_id" type="string" required>
  Unique per delivery. Use it to de-duplicate.
</ResponseField>

<ResponseField name="reference_id" type="string">
  The `reference_id` you supplied when sending, if any.
</ResponseField>

<ResponseField name="channel_used" type="string">
  `rcs` or `sms`: how the client got the message. Can be null on `message.sent` with `channel: "auto"`, before the carrier reports it.
</ResponseField>

<ResponseField name="clinic_id" type="string" required>
  The practice the message was sent for.
</ResponseField>

<ResponseField name="occurred_at" type="string" required>
  When the status changed (ISO 8601).
</ResponseField>

## Verifying Webhook Signatures

Signatures work the same way as the [AI outbound outcome webhook](/api-reference/ai_outbound/outcome_webhook#verifying-webhook-signatures) and use the same practice secret. When it's configured, each request carries `X-Webhook-Signature`: the HMAC-SHA256 hex digest of the raw request body. Verify it with a constant-time comparison before processing the payload.

## Delivery and Retries

- Webhooks are an HTTP POST with a `Content-Type: application/json` body and a `User-Agent` of `Oliver-Messages/1.0`.
- Your `callback_url` must be `https://`. Oliver verifies the TLS certificate and allows 10 seconds for a response.
- Respond with a `2xx` status code to acknowledge receipt.
- If your endpoint doesn't respond successfully, Oliver makes up to 3 attempts in total (waiting 2s, then 4s). After that the status isn't retried on its own, but the next status change sends the latest status. Use [`GET /messages/{id}`](/api-reference/messages/show) to catch up.
